> [!note] 摘要
> 系统梳理 decoder-only Transformer 的三层量化分析框架：**参数量**（各模块来源与总公式）、**计算量 FLOPs**（前向/训练/推理的 prefill 与 decode 分离推导）、**显存占用**（训练时参数+梯度+优化器+激活，推理时权重+KV cache）。覆盖标准 MHA 及 SwiGLU、GQA/MQA 等现代变体，附经典近似公式与 scaling 规律。运行性能、系统瓶颈、分布式代价已拆分至 [[大模型系统性能优化]]。

## 0. 统一符号

| 符号 | 含义 |
|------|------|
| $V$ | vocab size |
| $d$ | hidden size |
| $L$ | Transformer block 层数 |
| $d_{\text{ff}}$ | FFN 中间维度 |
| $T$ | 序列长度（训练/推理时含义略有不同） |
| $T_0$ | 推理 prompt 长度 |
| $h$ | attention head 数 |
| $d_h$ | 每 head 维度，$d = h \cdot d_h$ |
| $B$ | batch size |
| $N$ | decode 阶段新生成 token 数 |
| $P$ | 模型总参数量 |
| $b_w, b_g, b_a, b_{kv}$ | 参数/梯度/激活/KV cache 每元素字节数 |

精度对应字节数：fp32 → 4B，fp16/bf16 → 2B，int8 → 1B，int4 → 0.5B。

> [!tip] 核心原则
> - **参数量** = 元素个数（与 $B, T$ 无关）
> - **FLOPs** = 矩阵乘法中的乘加次数（随 $B, T, L, d$ 变化）
> - **显存** = 元素个数 × 每元素字节数

## 第一层：模型本体——参数量计算

### 1. Embedding 层

Token embedding：每个 token 对应一个 $d$ 维向量，共 $V$ 个：

$$P_{\text{token\_emb}} = V \cdot d$$

Position embedding 仅在**可学习位置编码**时存在（最大长度 $T$）：

$$P_{\text{pos\_emb}} = T \cdot d$$

若使用 [[位置编码]]（RoPE / 正弦编码 / ALiBi），则此项 ≈ 0。Embedding 总计：

$$P_{\text{emb}} = Vd \quad (\text{无可学习位置编码})$$

### 2. Transformer Block

一个 block 由 Self-Attention + FFN + Norm 组成。

**Self-Attention**：四个线性层 $W_Q, W_K, W_V, W_O \in \mathbb{R}^{d \times d}$：

$$P_{\text{attn}} = 4d^2$$

**FFN**（标准版，两层线性 $d \to d_{\text{ff}} \to d$）：

$$P_{\text{ffn}} = 2d \cdot d_{\text{ff}}$$

取经典设定 $d_{\text{ff}} = 4d$ 时：

$$P_{\text{ffn}} = 8d^2$$

**Norm**：每层两个 LayerNorm（scale + bias）= $4d$，或 RMSNorm（仅 scale）= $2d$。相对于 $d^2$ 是小项，手算时常忽略。

单层 block 总计（忽略 norm）：

$$P_{\text{block}} \approx 4d^2 + 2dd_{\text{ff}}$$

$d_{\text{ff}} = 4d$ 时得到最常用的近似：

$$P_{\text{block}} \approx 12d^2$$

$L$ 层合计：

$$P_{\text{blocks}} \approx L(4d^2 + 2dd_{\text{ff}}) \approx 12Ld^2$$

### 3. LM Head

将 hidden state 映射回 vocab logits：

$$P_{\text{lm\_head}} = d \cdot V$$

> [!note] 权重共享（Weight Tying）
> 很多语言模型让 lm head 与 token embedding 共享权重：$W_{\text{lm\_head}} = W_{\text{token\_emb}}^\top$。此时 lm head 不新增参数，$P_{\text{lm\_head}} = 0$（额外新增）。

### 4. 总参数量汇总

不共享 lm head + 可学习位置编码：

$$P_{\text{total}} = (Vd + Td) + L(4d^2 + 2dd_{\text{ff}}) + dV$$

常见近似（不算位置编码和 norm）：

$$P_{\text{total}} \approx 2Vd + L(4d^2 + 2dd_{\text{ff}})$$

$d_{\text{ff}} = 4d$ 时：

$$P_{\text{total}} \approx 2Vd + 12Ld^2$$

若 lm head 与 embedding 共享：

$$P_{\text{total}} \approx Vd + 12Ld^2$$

### 5. 现代变体对参数量的影响

| 变体 | 影响 | 参数量变化 |
|------|------|-----------|
| SwiGLU / GLU | FFN 多一个门控投影 | $2dd_{\text{ff}} \to \frac{8}{3}dd_{\text{ff}}$ |
| GQA / MQA | K/V head 数减少 | K/V 投影参数 < $d^2$ |

> [!warning] head 数 $h$ 的作用
> 在标准 MHA 中，$h$ 影响内部计算过程但**不改变总参数量**——Q/K/V/O 仍然是 $d \to d$ 的映射。GQA/MQA 下除外。

## 第二层：计算量——FLOPs 推导

FLOPs 计数约定：$(m,n) \times (n,p) \to (p,m)$ 的矩阵乘法记为 $2mnp$ FLOPs（含乘法和加法）。以下统计**主干 FLOPs**（大矩阵乘法），忽略 embedding 查表、softmax、Norm、激活函数等小项。

### 1. 单层 block 前向 FLOPs

输入 $X \in \mathbb{R}^{B \times T \times d}$。

**Q/K/V/O 四个线性层**：每个是 $(B,T,d) \times (d,d)$，单个 $2BTd^2$，四个合计：

$$F_{QKVO} = 8BTd^2$$

**Attention 分数矩阵** $QK^\top \in \mathbb{R}^{T \times T}$，每元素为长度 $d$ 的点积：

$$F_{QK^\top} = 2BT^2d$$

**Attention 输出** $\text{scores} \times V$：$(T,T) \times (T,d) \to (T,d)$：

$$F_{\text{attn} \cdot V} = 2BT^2d$$

Attention 主体两步合计：$F_{\text{attn-main}} = 4BT^2d$

**FFN 两层**：上投影 $(B,T,d) \times (d,d_{\text{ff}})$ + 下投影 $(B,T,d_{\text{ff}}) \times (d_{\text{ff}},d)$：

$$F_{\text{FFN}} = 4BTdd_{\text{ff}}$$

$d_{\text{ff}} = 4d$ 时：$F_{\text{FFN}} = 16BTd^2$

**单层 block 总计**：

$$F_{\text{block}} = 8BTd^2 + 4BT^2d + 4BTdd_{\text{ff}}$$

$d_{\text{ff}} = 4d$ 时：

$$\boxed{F_{\text{block}} = 24BTd^2 + 4BT^2d}$$

### 2. 整模型一次前向

$L$ 层 blocks + lm head $(B,T,d) \times (d,V)$：

$$F_{\text{fwd}} \approx L(8BTd^2 + 4BT^2d + 4BTdd_{\text{ff}}) + 2BTdV$$

$d_{\text{ff}} = 4d$ 时：

$$\boxed{F_{\text{fwd}} \approx L(24BTd^2 + 4BT^2d) + 2BTdV}$$

### 3. 训练 FLOPs

反向传播包含前向 + 对输入梯度 + 对权重梯度，粗略近似：

$$\boxed{F_{\text{train}} \approx 3 F_{\text{fwd}}}$$

即：

$$F_{\text{train}} \approx L(72BTd^2 + 12BT^2d) + 6BTdV$$

### 4. 推理 FLOPs：Prefill 与 Decode 分离

推理必须分两段处理，因为计算形式不同。

#### 4.1 Prefill

Prompt 长度为 $T_0$，本质是一次完整前向并建立 [[KV Cache]]：

$$F_{\text{prefill}} \approx L(24BT_0d^2 + 4BT_0^2d) + 2BT_0dV$$

attention 仍含 $T_0^2$ 平方项。

#### 4.2 Decode 单步

当前上下文长度 $T$，生成 1 个新 token。输入形状退化为 $(B, 1, d)$，但需与历史 KV cache 交互。

- Q/K/V/O 四个线性层：$8Bd^2$
- Attention（当前 Q 与历史 K/V 匹配）：$4BTd$（不再是 $T^2d$）
- FFN：$4Bdd_{\text{ff}}$

单层 decode-step：

$$F_{\text{block, decode-step}} = 8Bd^2 + 4BTd + 4Bdd_{\text{ff}}$$

整模型单步（含 lm head）：

$$\boxed{F_{\text{decode-step}} \approx L(8Bd^2 + 4BTd + 4Bdd_{\text{ff}}) + 2BdV}$$

> [!tip] KV cache 的关键作用
> 将 decode 阶段的 attention 从 $O(T^2)$ 降到 $O(T)$。历史 K/V 不必重算，只需缓存复用。

#### 4.3 连续生成 N 个 token

第 $i$ 步上下文长度 $T_i = T_0 + i - 1$，总 decode FLOPs：

$$F_{\text{decode,total}} \approx BLN(8d^2 + 4dd_{\text{ff}}) + 4BLd \sum_{i=1}^{N} T_i + 2BNdV$$

其中 $\sum_{i=1}^{N} T_i = NT_0 + \frac{N(N-1)}{2}$。

完整推理总 FLOPs：

$$F_{\text{infer}} = F_{\text{prefill}} + F_{\text{decode,total}}$$

### 5. Scaling 规律总结

从单层公式 $F_{\text{block}} = 24BTd^2 + 4BT^2d$ 出发：

| 变量 | 增长阶 | 说明 |
|------|--------|------|
| $B$（batch size） | $O(B)$ | 线性 |
| $L$（层数） | $O(L)$ | 线性 |
| $d$（hidden size） | $O(d^2)$ 主导 | QKV/O 和 FFN 为平方项；attention 对 $d$ 本身是线性 |
| $T$（序列长度） | $O(T) + O(T^2)$ | QKV/FFN 为线性；**attention 为平方** |

Decode 阶段 attention 降为 $O(T)$（感谢 KV cache），这是长上下文推理的核心瓶颈所在。

## 第三层：显存占用

分两条线分析：**训练**（参数 + 梯度 + 优化器 + 激活）和**推理**（权重 + [[KV Cache]] + 运行时 buffer）。

$$M_{\text{train}} = M_{\text{param}} + M_{\text{grad}} + M_{\text{opt}} + M_{\text{act}}$$

$$M_{\text{infer}} = M_{\text{param}} + M_{\text{KV}} + M_{\text{runtime}}$$

### 1. 参数显存

$$M_{\text{param}} = P \cdot b_w$$

例：7B 模型 bf16 → $7 \times 10^9 \times 2 \approx 14$ GB。

### 2. 梯度显存

每个参数对应一个梯度：

$$M_{\text{grad}} = P \cdot b_g$$

通常与参数同量级（bf16 梯度 → $2P$）。

### 3. Optimizer State 显存

以 Adam/AdamW 为例，需保存一阶动量 $m$ 和二阶动量 $v$（均与参数同形，fp32 存储）：

$$M_{\text{opt}} \approx 8P \quad (\text{仅 } m, v)$$

混合精度训练若额外维护 fp32 master weights：

$$M_{\text{opt}} \approx 12P \quad (+ \text{master weights})$$

**常见训练总账**（bf16 参数 + bf16 梯度 + AdamW + fp32 master）：

| 分项 | 占用 |
|------|------|
| 参数 | $2P$ |
| 梯度 | $2P$ |
| 优化器状态 | $12P$ |
| **合计** | **$\approx 16P$** |

这就是 Adam 训练显存消耗大的根本原因。

### 4. Activation 显存

训练时反向传播需要保留前向中间结果，这是最容易爆的部分。

粗略估计：每层产生若干 $(B,T,d)$ 形状的中间张量，总计：

$$M_{\text{act}} \approx c \cdot BTLd \cdot b_a$$

$c$ 为实现相关常数（不同框架、是否 checkpoint、是否 [[Flash Attention]] 均会影响）。

> [!warning] 为什么 activation 容易爆
> 参数显存固定为 $P$ 的函数，但 activation 随 $B$、$T$、$L$、$d$ 一起增长。很多时候不是模型装不下，而是 **batch 一大就爆、sequence 一长就爆**——爆的是 activation。

**Naive attention 的额外开销**：如果显式保存 attention score 矩阵 $(B, h, T, T)$，会多出：

$$M_{\text{attn-map}} \approx B \cdot h \cdot T^2 \cdot b_a$$

这一项随 $T^2$ 增长，长序列下非常可怕。[[Flash Attention]] 的核心价值之一就是不物化完整的 $T \times T$ attention 矩阵，显著降低此开销。

**Gradient Checkpointing**：前向少存激活，反向时重算中间结果——典型的**用算力换显存**策略。

### 5. KV Cache 显存（推理核心）

标准 MHA 下，每个 token 在每层缓存一个 Key 和一个 Value 向量（各 $d$ 维）：

$\boxed{M_{\text{KV}} = 2BLTd \cdot b_{kv}}$

fp16/bf16 时：$M_{\text{KV}} = 4BLTd$ Byte。

[[MHA变体：MQA与GQA]] 下，KV head 数 $n_{\text{kv}} < h$：

$M_{\text{KV}} = 2BLT \cdot n_{\text{kv}} d_h \cdot b_{kv}$

KV cache 随推理过程持续增长（每生成一个 token，$T$ 加 1），这也是长上下文推理和高并发推理吃显存的主因。

### 6. 显存小结

| 场景  | 主要组成                           | 主导项                              |
| --- | ------------------------------ | -------------------------------- |
| 训练  | 参数 + 梯度 + 优化器 + 激活             | 小模型→优化器状态；大 batch/长序列→activation |
| 推理  | 权重 + KV cache + runtime buffer | 模型权重 + KV cache                  |

最该记住的五个公式：

$$
\begin{aligned}
M_{\text{param}} &= P \cdot b_w \\
M_{\text{grad}} &= P \cdot b_g \\
M_{\text{opt}} &\approx 8P \sim 12P \\
M_{\text{act}} &\approx c \cdot BTLd \cdot b_a \\
M_{\text{KV}} &= 2BLTd \cdot b_{kv} \\
\end{aligned}
$$

> [!warning] 易错点
>
> - **head 数 $h$ 不改变 MHA 总参数量**（Q/K/V/O 仍为 $d \to d$），但 GQA/MQA 下例外
> - **LM head 权重共享时不新增参数**，容易漏算或重复算
> - **SwiGLU 使 FFN 参数从 $2dd_{\text{ff}}$ 增至 $\frac{8}{3}dd_{\text{ff}}$**，用 $12d^2$ 近似会偏小
> - **训练 FLOPs ≈ 3× 前向**是粗略近似**，实际还涉及 loss 计算等额外开销
> - **Activation 爆的不是参数而是中间张量**，增大 $B$ 或 $T$ 时首先遇到的是这个瓶颈
> - **Decode 的 attention 是 $O(T)$ 不是 $O(T^2)$**，KV cache 已经把平方项消掉了
> - **AdamW 优化器状态约 12P（含 master weights）**，远大于参数本身（2P），是训练显存的大头
