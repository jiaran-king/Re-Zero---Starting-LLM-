# 稀疏注意力

> [!note]
> 通过约束注意力连接范围来降低计算和显存成本的方案族。标准 self-attention 是稠密连接（$O(S^2)$），稀疏注意力只保留部分有价值的连接，将复杂度降到近似线性。局部注意力和滑动窗口注意力是其中最常见的形式。

---

## 为什么需要

标准 attention 中，序列长度为 $S$ 时每个 token 要与全部 $S$ 个 token 计算相关性，attention 矩阵大小 $S \times S$，计算复杂度 $O(S^2)$。上下文越长，这个代价越不可接受。

核心思路很直接：**不让每个 token 看全部位置，只看最有价值的一部分**。

## 三者的层级关系

$$\text{滑动窗口 Attention} \subset \text{局部 Attention} \subset \text{稀疏 Attention}$$

- **稀疏注意力**是最一般的框架：任意"只保留部分连接"的 attention 模式
- **局部注意力**是特例：只允许关注附近邻域
- **滑动窗口注意力**是局部注意力最典型的实现：固定大小的连续窗口沿序列滑动

## 局部注意力

设窗口半径为 $w$，第 $i$ 个位置的可见邻域：

$$\mathcal{N}(i) = \{j \mid i - w \le j \le i\}$$

（因果模型中只看左侧，双向模型中两侧都看）

远离当前位置的 token 被 mask 为 $-\infty$，不参与 softmax。复杂度从 $O(S^2)$ 降到 $O(Sw)$。

局限在于单层无法直接捕获远距离依赖——信息需要靠多层堆叠逐步传播，和卷积网络中小感受野多层叠加后扩大感受野的原理一样。

## 滑动窗口注意力

窗口长度为 $w$ 时，第 $i$ 个 token 只看 $[i-w+1,\, i]$ 范围内的 token。随着 $i$ 前进，窗口同步滑动。

举例（$w=4$）：
- token 5 → 看 2,3,4,5
- token 6 → 看 3,4,5,6
- token 7 → 看 4,5,6,7

结构规整、易于工程实现，适合与 causal mask 结合。Mistral 等模型在部分层中使用滑动窗口注意力来平衡效果和效率。

## 更一般的稀疏模式

除了局部窗口外，还有几种常见设计：

| 模式 | 做法 | 目的 |
|------|------|------|
| 局部稀疏 | 只看附近固定窗口 | 降低基础计算量 |
| 跳跃式稀疏 | 额外允许每隔固定间隔采样远处 token | 以较小代价接触远距离信息 |
| 全局 + 局部 | 特殊 token 充当全局信息中转站 | 弥补局部窗口无法跨远距通信的问题 |
| 块稀疏 | 序列分块，只允许部分块之间互相 attention | 规整结构，便于硬件并行 |

## 复杂度与感受野

| 方案 | 复杂度 | 远距离依赖 |
|------|--------|-----------|
| 全 attention | $O(S^2)$ | 一跳直达 |
| 局部 / 滑动窗口 | $O(Sw)$ | 多层传播 |
| 设计良好的稀疏 attention | $O(Sw)$ ~ $O(S \log S)$ | 少量远程连接辅助 |

一个关键点：**局部注意力不等于模型永远看不到远处信息**。一层只能看左右各 $w$ 个 token，但多层堆叠后等效感受野会不断扩大。全 attention 的优势是远程依赖可以一跳直达；局部/稀疏方案的优势是用低得多的代价覆盖大部分实际需求——很多任务中局部依赖本身就占主导地位。

> [!warning]
> - 理论复杂度下降不一定转化为实际的同比加速——稀疏操作在 GPU 上未必比稠密矩阵乘法更快
> - 稀疏模式设计不当会损害信息流动，效果损失可能超过预期
> - "长上下文"问题不能仅靠稀疏注意力解决，通常需要配合 KV Cache 压缩等其他技术
