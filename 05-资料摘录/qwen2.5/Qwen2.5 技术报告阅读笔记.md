# Qwen2.5 技术报告

> [!info] 原始来源
> [Qwen2.5 Technical Report](https://arxiv.org/abs/2412.15115)

> [!note] 一句话
> Qwen2.5 的提升不是来自架构革命，而是预训练 + 后训练的全链路系统升级：数据从 7T 扩到 18T，后训练用超 100 万条 SFT 数据配合多阶段强化学习（离线 DPO + 在线 GRPO），最终在更小参数量下逼近甚至超越更大模型。

## 1 模型系列与定位

Qwen2.5 不是单一模型，而是一整条尺寸带，同时覆盖两条产品线：

| 产品线 | 模型 | 参数规模 |
|--------|------|----------|
| **Dense（开源）** | Base / Instruct | 0.5B、1.5B、3B、7B、14B、32B、72B |
| **MoE（API）** | Turbo / Plus | — |

总体改进概括为三条主线：**Better in Size**（补回 3B/14B/32B）、**Better in Data**（预训练 18T + 后训练 ~100 万样本）、**Better in Use**（生成长度 2K→8K，增强结构化输入输出和工具使用，Turbo 支持到 1M 上下文）。

## 2 架构与 Tokenizer

Dense 模型延续 Transformer decoder，配置为 GQA + SwiGLU + RoPE + QKV bias + RMSNorm。MoE 模型则在 FFN 层做专家化扩展。Tokenizer 仍为 BBPE，control tokens 从 3 个扩展到 22 个，形成统一词表。

> [!tip] 架构不是这篇报告的重点
> 从篇幅和强调重点看，真正的核心在 Pre-training 和 Post-training。架构部分相对稳健，更多是在成熟范式上做配置和扩展。现代大模型的进步越来越依赖训练链路优化，而不只是新架构。

## 3 预训练：把基础能力上限做高

预训练解决的不是"让模型更听话"，而是让模型更有知识、更会推理、更会代码、更能处理长上下文。报告把它拆成三个子模块。

### 3.1 预训练数据：四维升级

数据提升不只是 token 数量从 7T 到 18T，更是质量、领域分布和信息密度的全面升级：

| 改进方向 | 解决的问题 | 做法 |
|----------|-----------|------|
| 更好的数据过滤 | 低质量网页数据太多（噪声、重复、模板化、机器生成内容） | 用 Qwen2-Instruct 做质量过滤器，多维分析和打分 |
| 更好的数学和代码数据 | 通用网页语料对高难能力支持不足 | 将 Qwen2.5-Math 和 Qwen2.5-Coder 的数据并入预训练底座 |
| 更好的合成数据 | 高质量领域数据天然稀缺 | 用 Qwen2-72B-Instruct 和 Qwen2-Math-72B-Instruct 生成合成数据，再经 reward model 过滤 |
| 更好的 data mixture | 数据分布失衡（电商/社媒过度代表，科技/科学/学术不足） | 对过度代表域下采样、对高价值域上采样 |

模型变强首先取决于吃进去的东西是否更好，而不只是吃进去多少。模型能力由 token 总量和 token 的**结构**共同决定——18T tokens 如果分布不合理，效果可能不如精心配比的更小规模数据。

> [!tip] 数据 mixture 是一门独立的工程
> 网页数据的天然偏斜问题意味着现代大模型训练已经不是"把互联网全喂进去"，而是需要主动做数据分布工程。

### 3.2 超参数选择：Scaling Law 的应用

Scaling Law 在这里不只用来决定模型大小，更关键的是用来找最优的 **batch size 和 learning rate**，并同时应用于 dense 和 MoE 两种架构：

1. **经验调参成本太高**——每个尺寸都靠大量实验手工找最优配置不现实，scaling law 把零散经验变成可预测规律
2. **dense 和 MoE 的最优训练区间不同**——参数组织、激活量、训练稳定性都有差异，不能简单照搬一套超参数

### 3.3 长上下文预训练：训练期 + 推理期两层

长上下文能力不是单一技巧，而是训练阶段和推理阶段的组合策略：

| 模型类型 | 训练期扩展 | 推理期外推 | 最终支持长度 |
|----------|-----------|-----------|-------------|
| 普通 Dense 模型 | 4K → 32K（两阶段） | YARN + DCA | 128K |
| Turbo（MoE） | 32K → 64K → 128K → 256K（渐进式） | YARN + DCA | 1M |

位置编码方面提高 RoPE base frequency，并用 ABF 等方法改进长度扩展。后续评测专门比较了有无 DCA+YARN 的差异——这不是装饰性技巧，而是长上下文能力真正成立的关键环节。

推理期外推（YARN、DCA）建立在训练期扩展的基础上才能可靠工作，两者缺一不可。

## 4 后训练：把潜力变成可用助手

预训练学世界知识和通用模式，后训练学"怎么回答更符合人类要求"。后训练已演化为一个三段式流水线：SFT → Offline RL → Online RL，每段处理的信号性质不同，解决的问题也不同。

> [!warning] 三段式的顺序不能随意排列
> SFT 必须在前——没有足够的示范数据，RL 无从优化。Offline RL 在 Online RL 之前——先用确定性强的可验证信号建立底线，再引入 reward model 处理更主观的偏好维度。

### 4.1 SFT：系统修补九类短板

SFT 不是随便堆数据，而是在系统修补旧模型的常见缺陷，最终构造了超过 100 万条样本：

| 方向                    | 解决的问题                 | 关键做法                                                               |
| --------------------- | --------------------- | ------------------------------------------------------------------ |
| 长文本生成                 | 会答但答不长、答不稳            | 专门构造 long-response dataset，输出长度拉到 8,192 tokens                     |
| 数学                    | 给答案但不展示推理过程           | 引入 CoT 数据，rejection sampling + reward modeling 保证过程质量              |
| 代码                    | 看起来对但不一定能跑            | 多语言 agent 生成 + sandbox 静态检查 + 单元测试验证                               |
| Instruction Following | 理解指令不够严格              | LLM 同时生成指令/验证代码/unit tests，execution feedback 做 rejection sampling |
| 结构化数据理解               | 表格、JSON 推理不够强         | 表格问答、事实核验、纠错 + reasoning chains                                    |
| 逻辑推理                  | 会背知识但不会系统推理           | 70,000 条多形式推理查询，反复过滤错误答案和 flawed reasoning                         |
| 跨语言迁移                 | 能力无法迁移到低资源语言          | 翻译高资源语言的指令和答案，检查语义一致性                                              |
| System Prompt 鲁棒性     | system prompt 一换表现就波动 | 数百种 general system prompts 训练                                      |
| Response Filtering    | 训练数据回答质量不一致           | critic model + multi-agent scoring system 筛选                       |

> [!tip] 代码训练的本质区别
> 代码比普通文本更容易通过执行反馈进行客观验证——这是代码训练方法论不同于一般文本训练的关键前提。

### 4.2 Offline RL（DPO）：利用可验证信号

有些任务"答案对不对"很重要，但 reward model 不一定能稳定判别。报告点名了数学、代码、instruction following、逻辑推理这几个领域。

做法是：先让 SFT 模型重采样回答，通过质检的当正样本，失败的当负样本，然后做 DPO。本质是利用**可验证信号**（标准答案、执行结果、可验证规则），而不是依赖一个泛化很强但可能不够可靠的 reward model。

### 4.3 Online RL（GRPO）：优化人类偏好

另一类问题：答案未必只有唯一正确形式，但人会明显偏好某些回答风格。关注的维度包括 truthfulness、helpfulness、conciseness、relevance、harmlessness、debiasing。采用 GRPO（组内相对策略优化）进行在线优化。

Offline RL 和 Online RL 的分工：

| | Offline RL (DPO) | Online RL (GRPO) |
|--|------------------|-------------------|
| 适合的任务类型 | 客观、可验证、标准明确 | 主观、偏好型、质量连续变化 |
| 典型领域 | 数学、代码、指令跟随、逻辑推理 | 真实性、有用性、简洁性、安全性、去偏 |
| 训练信号来源 | 可提前构造的偏好对 | 在线交互 + Reward Model |

二者不是"先 offline 再 online"的能力进阶关系，而是并行处理两类不同性质的目标。DPO 处理客观可验证任务，GRPO 处理主观偏好。

### 4.4 长上下文 Fine-tuning：对齐长场景下的行为

"能读长文"不等于"在长文条件下还能表现得像个好助手"。这一步主要针对 Turbo，SFT 分两步走：先只训短指令，再混合短指令和最长到 262,144 tokens 的长指令。RL 阶段仍主要基于短指令——因为长上下文 RL 成本太高，且缺少合适的 reward model。

这是一种折中路线：先用 SFT 把长上下文下的指令跟随拉起来，再用短指令 RL 提升整体偏好质量。

## 5 评测：分层验证

评测针对不同训练阶段的产物分别验证：

| 评测对象           | 关注重点                | 典型 Benchmark                             |
| -------------- | ------------------- | ---------------------------------------- |
| Base Model     | 语言理解、常识问答、数学、代码、多语言 | MMLU、GSM8K、HumanEval 等                   |
| Instruct Model | 人类偏好和对齐             | IFEval、Arena-Hard、MT-Bench、LiveCodeBench |
| Reward Model   | 偏好判别能力              | 专用偏好评测集                                  |
| Long Context   | 长序列理解和生成            | "大海捞针"、长文档 QA                            |

评测应该回答"这个阶段的产物是否达到了预期目标"，而不是只看最终分数高低。Base Model 的评测验证预训练是否灌入了足够的基础能力；Instruct Model 的评测验证后训练是否成功将能力转化为可用输出；Reward Model 的评测则确保 RL 阶段的信号源本身可靠。

> [!tip] RM benchmark 高 ≠ RL 效果好
> 报告暗示 reward model benchmark 分数高不一定带来更好的 RL 最终效果。"judge 强"不等于"训出来的 policy 强"——评测 RM 本身也需要独立的方法论。

## 6 设计思想

Qwen2.5 的提升不是单点突破，而是**预训练数据工程、超参数系统优化、长上下文组合策略、多阶段后训练流水线、信号分层建模、分层评测**六条线协同推进的结果——每条线背后都有明确的设计决策和工程取舍。

### 6.1 数据工程决定基础能力上限

模型变强首先取决于吃进去的东西是否更好，而不只是吃进去多少。模型能力由 token 总量和 token 的**结构**共同决定。18T tokens 如果分布不合理，效果可能不如精心配比的更小规模数据。

网页数据的天然偏斜问题（电商/社媒过度代表，科技/科学/学术不足）意味着现代大模型训练已经不是"把互联网全喂进去"，而是需要主动做**数据分布工程**。

### 6.2 超参数可以通过 Scaling Law 系统优化

Scaling Law 不只用来决定模型大小，更关键的作用是**系统性地寻找最优 batch size 和 learning rate**。它把零散经验变成可预测规律，让超参数选择从"试错"变成"计算"，同时为 dense 和 MoE 两种架构分别建立最优配置映射。

### 6.3 长上下文是训练与推理协同的系统工程

长上下文不是靠改一下位置编码就能解决的问题，而是**训练期扩展 + 推理期外推**两层手段的组合。推理期外推（YARN、DCA）建立在训练期扩展的基础上才能可靠工作，两者缺一不可。

### 6.4 后训练已演化为多阶段对齐流水线

后训练不再是单一的 SFT 或 RLHF，而是一个**三段式流水线**：SFT → Offline RL → Online RL。每段处理的信号性质不同：

- **SFT**：先把能力补齐（系统性修补基座模型的已知短板）
- **Offline RL（DPO）**：再用可验证信号校准（数学、代码、指令跟随等客观任务）
- **Online RL（GRPO）**：最后用在线探索精修偏好（真实性、有用性、简洁性等主观维度）

三段式的顺序不能随意排列——SFT 必须在前提供示范数据，Offline RL 在 Online RL 之前先用确定性强的信号建立底线。

### 6.5 可验证信号与偏好信号需要分开建模

DPO 和 GRPO 不是"先 offline 再 online"的能力进阶关系，而是**并行处理两类不同性质的目标**：

| 维度 | Offline RL (DPO) | Online RL (GRPO) |
|------|------------------|-------------------|
| 任务类型 | 客观、可验证、标准明确 | 主观、偏好型、质量连续变化 |
| 典型领域 | 数学、代码、指令跟随、逻辑推理 | 真实性、有用性、简洁性、安全性、去偏 |
| 信号来源 | 可提前构造的偏好对 | 在线交互 + Reward Model |
| 核心优势 | 不依赖泛化能力可能不足的 reward model | 能探索和优化 reward model 覆盖不到的细微偏好 |

DPO 的本质是利用**可验证信号**（标准答案、执行结果、可验证规则）；GRPO 则关注人类会明显偏好的回答风格，采用组内相对策略优化进行在线探索。

### 6.6 评测的本质是构建能力画像

评测应该回答"这个阶段的产物是否达到了预期目标"，而不是只看最终分数高低。针对训练链路中每个阶段的产物分别验证：Base Model 验证预训练是否灌入足够的基础能力；Instruct Model 验证后训练是否成功将能力转化为可用输出；Reward Model 确保 RL 阶段的信号源本身可靠。

一个值得注意的点：reward model benchmark 分数高不一定带来更好的 RL 最终效果。"judge 强"不等于"训出来的 policy 强"——评测 RM 本身也需要独立的方法论。

## 7 核心结论

如果要把整篇报告压缩成一条逻辑链：

**确定产品线和模型形态 → 用架构定义容量与计算形式 → 通过预训练灌入基础能力 → 通过后训练塑造行为风格 → 通过评测验证结果。**

最强的 claim 不是"某个 benchmark 第一"，而是**在更小参数量下综合能力逼近甚至部分超过更大模型**——72B-Instruct 对比 Llama-3-405B-Instruct 具有竞争力，Turbo/Plus 对比 GPT-4o-mini 和 GPT-4o 强调成本效益。

## 可拆分概念

以下概念可以从本篇分析笔记中进一步拆分为独立的概念笔记：

- **数据分布工程**（data mixture / domain balancing）——涵盖下采样、上采样、领域数据配比
- **Scaling Law 超参数优化**——涵盖 batch size / learning rate 的 scaling law 预测
- **长上下文组合策略**——涵盖训练期扩展 + 推理期外推的双层方法
- **三段式后训练范式**（SFT → Offline RL → Online RL）
- **可验证信号 vs 偏好信号**——涵盖 DPO/GRPO 的分工逻辑
- **分层评测体系**

> [!warning] 容易混淆的点
> - **预训练 vs 后训练的职责边界**：预训练决定模型"原始上限"有多高（知识、推理、代码、长上下文基础能力）；后训练决定这些能力能不能变成稳定、可控、符合人类偏好的输出。两者是串行关系，不是替代关系。
> - **Offline RL ≠ Online RL 的简化版**：二者解决不同性质的问题。Offline RL 利用可验证信号处理客观任务；Online RL 通过 reward model 处理主观偏好。
> - **长上下文的两层技术不要混为一谈**：训练期扩展（逐步增加训练序列长度）和推理期外推（YARN、DCA）是独立的两层手段，后者在前者的基础上才能可靠工作。
