
# 第四部分：Pre-Training 学习笔记

> [!info] 原始来源
> [DeepSeek-V4 官方模型卡 / Technical Report](https://huggingface.co/deepseek-ai/DeepSeek-V4-Pro)

## 一、章节定位

第 4 节是整篇论文中承上启下的一部分。前面第 2 节讲架构，包括 CSA/HCA、mHC、Muon；第 3 节讲训练和推理基础设施；第 4 节则把这些设计真正落到预训练流程里。它主要包括三块：**4.1 Data Construction、4.2 Pre-Training Setups、4.3 Evaluations**。

这一节评估的是 **base model**，不是最终聊天模型，也不是经过强化学习或 on-policy distillation 后的模型。因此，第四部分的重点是“底座能力”而不是“对话能力”。

---

## 二、4.1 Data Construction：数据构造

4.1 的核心思想是：DeepSeek-V4 在 DeepSeek-V3 预训练数据的基础上，构造了一个 **更多样、更高质量、有效上下文更长** 的训练语料库。作者强调持续改进 data construction pipeline，尤其是提升 web 数据质量、数学与代码数据、agentic data、多语言数据和长文档数据。

### 1. Web 数据：过滤自动生成和模板化内容

论文提到，对于网页来源的数据，DeepSeek-V4 加入过滤策略，去除批量自动生成内容和模板化内容，以降低 **model collapse** 风险。这里的意思是，如果模型大量训练在低质量、重复、机器生成、模板化文本上，它可能会学习到低熵、重复化的表达模式，导致生成质量下降。

所以这一点不是简单地“多爬网页”，而是强调 **web 数据清洗质量**。在大模型预训练里，网页数据规模很大，但噪声也最大；过滤策略的目标是让模型学到真实、多样、有信息量的文本分布。

### 2. 数学和代码：仍然是核心数据

论文明确说，数学和编程语料仍然是训练数据的核心组成部分。数学数据主要增强模型的符号推理、多步推理和抽象问题求解能力；代码数据增强结构化生成、严格语法、长程依赖和工具型任务能力。

此外，DeepSeek-V4 在 mid-training 阶段加入了 **agentic data** 来增强代码能力。这里的 agentic data 可以理解为更接近“智能体完成任务”的数据，例如多步读代码、修改文件、运行测试、根据报错继续修复等任务轨迹。论文没有展开 agentic data 的具体构造细节，但从上下文看，它服务于更复杂的代码任务，而不只是普通代码补全。

### 3. 多语言数据：覆盖跨文化长尾知识

DeepSeek-V4 构建了更大的多语言语料库，以提升模型捕获不同文化中 **long-tail knowledge** 的能力。所谓长尾知识，就是低频、地区性、语言特定、领域特定或文化特定的知识。比如英文主流网页上反复出现的知识属于“头部知识”，而某个地区的历史人物、地方制度、非英语技术材料、本土考试体系、冷门专业术语等则属于“长尾知识”。

这一点说明，多语言数据不只是为了翻译能力，也是在扩展模型的知识覆盖面。很多知识并不集中在英文互联网的高频区域，而分布在不同语言社区的长尾中。

### 4. 长文档数据：服务 1M 上下文能力

DeepSeek-V4 特别重视 long-document data curation，优先选择 scientific papers、technical reports 等具有独特学术价值的材料。

这和整篇论文的 1M token 主题直接相关。架构上的 CSA/HCA 让模型“能处理”长上下文，但数据上的长文档训练，才让模型真正学会在长上下文中保持主题、跨段落整合信息、利用远处证据、理解复杂文档结构。

### 5. 预处理策略：继承 V3，但加入 sample-level attention masking

DeepSeek-V4 基本沿用 DeepSeek-V3 的预处理策略：在 DeepSeek-V3 tokenizer 基础上增加少量用于 context construction 的特殊 token，词表大小仍保持 128K；同时继承 token-splitting 和 FIM，也就是 Fill-in-Middle 策略。论文还提到，它们会把不同来源的文档 pack 到合适的序列中，以减少 sample truncation；与 V3 不同的是，V4 在预训练中使用了 sample-level attention masking。

这里最重要的是 **document packing + sample-level masking**。packing 是为了把多个文档或样本拼到一个长序列里，提高训练效率并减少截断；sample-level masking 是为了防止拼在一起的独立样本互相 attend，避免模型误以为它们是连续上下文。

普通 causal mask 解决的是“不能看未来 token”；sample-level masking 解决的是“不能看别的样本”。两者通常叠加使用。

## 三、4.2 Pre-Training Setups：预训练设置

4.2 分成三块：模型设置、训练设置、训练不稳定性缓解。它是第四部分最工程化的一节。

## 4.2.1 Model Setups：模型设置

DeepSeek-V4 有两个 base model 路线：**DeepSeek-V4-Flash** 和 **DeepSeek-V4-Pro**。Flash 追求高效和低成本，Pro 追求更强能力和更高上限。

|项目|DeepSeek-V4-Flash|DeepSeek-V4-Pro|
|---|--:|--:|
|Transformer 层数|43|61|
|Hidden dimension|4096|7168|
|前两层注意力|Sliding window attention|HCA|
|后续注意力|CSA/HCA 交替|CSA/HCA 交替|
|CSA 压缩率 m|4|4|
|CSA attention top-k|512|1024|
|HCA 压缩率 m′|128|128|
|Routed experts|256|384|
|每 token 激活专家数|6|6|
|总参数|284B|1.6T|
|每 token 激活参数|13B|49B|

Flash 的前两层使用纯 sliding window attention，后续层交替使用 CSA 和 HCA；每层 MoE 有 1 个 shared expert 和 256 个 routed experts，每个 token 激活 6 个 routed experts，总参数 284B，每 token 激活 13B。

Pro 的规模明显更大：61 层、hidden dimension 7168，CSA top-k 提高到 1024，每层有 1 个 shared expert 和 384 个 routed experts，总参数 1.6T，每 token 激活 49B。

这里要抓住一个 MoE 模型的关键概念：**total parameters 不等于 activated parameters**。MoE 模型有很多专家，但每个 token 只路由到少数专家。因此模型可以拥有很大的总容量，同时保持较低的单 token 计算量。Flash 的 284B/13B 和 Pro 的 1.6T/49B，就是这种设计思想的体现。

## 4.2.2 Training Setups：训练设置

训练设置里最重要的关键词是：**Muon、AdamW、batch size scheduling、learning rate scheduling、sequence length curriculum、dense-to-sparse attention transition**。

### 1. 优化器设置

DeepSeek-V4-Flash 的大部分参数使用 Muon optimizer，但 embedding module、prediction head module 和所有 RMSNorm 权重使用 AdamW。AdamW 的参数为 β1=0.9、β2=0.95、ε=10⁻²⁰、weight decay=0.1；Muon 的 momentum=0.95、weight decay=0.1，并把每个 update matrix 的 RMS rescale 到 0.18，以复用 AdamW 的学习率设置。

这一点说明，DeepSeek-V4 并不是完全抛弃 AdamW，而是采用混合优化策略：大部分权重用 Muon，少数敏感模块仍用 AdamW。

### 2. Flash 的训练流程

DeepSeek-V4-Flash 训练 32T tokens，batch size 从小逐步增大到 75.5M tokens，并在多数训练阶段保持该 batch size。学习率前 2000 steps 线性 warmup，大部分训练阶段维持 2.7×10⁻⁴，最后按 cosine schedule 衰减到 2.7×10⁻⁵。序列长度从 4K 开始，逐步扩展到 16K、64K、1M。

注意力训练也采用课程式设计：先用 dense attention 训练前 1T tokens；到 64K 序列长度时引入 sparse attention；引入稀疏注意力时，先短暂 warm up CSA 的 lightning indexer，然后在后续大部分训练中使用 sparse attention。

这说明模型不是一开始就直接上 1M 上下文和稀疏注意力，而是先建立稳定的语言建模能力，再逐步扩大上下文长度和注意力稀疏度。

### 3. Pro 的训练流程

DeepSeek-V4-Pro 的训练设置大体与 Flash 一致，但超参数更适合大模型。Pro 训练 33T tokens，最大 batch size 是 94.4M tokens；峰值学习率是 2.0×10⁻⁴，末尾学习率是 2.0×10⁻⁵。它同样从 4K 序列长度开始，逐步扩展到 16K、64K、1M。相比 Flash，Pro 有更长的 dense attention 阶段，之后同样采用两阶段方式引入 sparse attention。

两个模型都使用 auxiliary-loss-free load balancing，bias update speed 设为 0.001；同时设置很小的 balance loss，权重为 0.0001，用于避免单个 sequence 内部出现极端专家负载不均衡。MTP loss weight 在大部分训练中为 0.3，在学习率开始衰减后降到 0.1。

## 4.2.3 Mitigating Training Instability：缓解训练不稳定

这一小节是第四部分最有工程价值的内容之一。作者指出，训练 trillion-parameter MoE 模型存在显著稳定性挑战。简单 rollback 可以临时恢复训练状态，但不能防止 loss spike 再次出现。经验上，spike 与 MoE 层中的 outlier 相关，而 routing mechanism 会加剧这些 outlier。

论文提出两个实用技巧：**Anticipatory Routing** 和 **SwiGLU Clamping**。

### 1. Anticipatory Routing

Anticipatory Routing 的核心是：**把 backbone network 的当前特征计算，和 routing network 的路由决策解耦**。

普通 MoE 训练中，step t 使用当前参数 θt 计算特征，也使用当前参数决定 token 路由到哪些专家。DeepSeek-V4 的做法是：在 step t，用当前参数 θt 做 feature computation，但 routing indices 使用历史参数 θt−Δt 计算。为了避免重复加载模型参数，它们会在 step t−Δt 提前取出 step t 的数据，预先计算并缓存 step t 的 routing indices。

系统层面，它们把 Anticipatory Routing 的额外 wall-clock overhead 控制到约 20%。更关键的是，它不是全程开启，而是在检测到 loss spike 后触发短暂 rollback，并只在此时启用 Anticipatory Routing；稳定一段时间后再回到标准训练。因此总体额外训练开销很小。

直观理解：Anticipatory Routing 是为了打断 routing 和 outlier 之间的恶性循环，避免“刚刚异常的路由网络继续把 token 分到更异常的专家”。

### 2. SwiGLU Clamping

SwiGLU Clamping 的思路更直接：限制 SwiGLU 中间激活的数值范围，以抑制异常值。论文说，在 Flash 和 Pro 的训练中，它们把 SwiGLU 的 linear component 限制在 [-10, 10]，并把 gate component 的上界限制为 10。该方法可以有效消除 outliers、稳定训练，同时不损害性能。

可以把这一小节总结为：

**Anticipatory Routing 处理 routing 诱发的不稳定；SwiGLU Clamping 处理激活值异常。前者从路由机制入手，后者从数值范围入手。**

## 四、4.3 Evaluations：预训练评估

4.3 的目标是验证：经过 4.1 的数据构造和 4.2 的训练设置后，DeepSeek-V4 的 base model 是否真的强于前代。

评估对象是三个 base model：**DeepSeek-V3.2-Base、DeepSeek-V4-Flash-Base、DeepSeek-V4-Pro-Base**。注意，这不是最终 post-training 模型。

## 4.3.1 Evaluation Benchmarks：评估基准

论文把 base model 评估分成四个维度：world knowledge、language understanding and reasoning、coding and mathematics、long-context processing。

| 评估维度                               | 代表 benchmark                                                                                | 主要测什么                |
| ---------------------------------- | ------------------------------------------------------------------------------------------- | -------------------- |
| World knowledge                    | AGIEval、C-Eval、MMLU、MMLU-Pro、MMMLU、MultiLoKo、Simple-QA verified、FACTS Parametric、TriviaQA 等 | 世界知识、事实记忆、多语言知识、长尾知识 |
| Language understanding & reasoning | BBH、DROP、HellaSwag、CLUEWSC、WinoGrande                                                       | 语言理解、常识推理、语义判断、上下文推理 |
| Coding & mathematics               | BigCodeBench、HumanEval、GSM8K、MATH、MGSM、CMath                                                | 代码生成、数学推理、结构化问题求解    |
| Long context                       | LongBench-V2                                                                                | 长上下文理解和处理能力          |

其中，Table 1 说明所有模型在统一内部评估框架和严格一致的设置下评估；分数差距不超过 0.3 被视为同一水平。表格也列出了三者规模：V3.2-Base 是 671B total / 37B activated，V4-Flash-Base 是 284B total / 13B activated，V4-Pro-Base 是 1.6T total / 49B activated。

---

## 4.3.2 Evaluation Results：评估结果

结果可以分成两条主线理解。

第一条主线是 **Flash 的效率故事**。DeepSeek-V4-Flash-Base 的总参数和激活参数都明显小于 DeepSeek-V3.2-Base，但它在大量 benchmark 上超过 V3.2-Base，尤其在世界知识任务和高难长上下文场景中表现突出。论文认为，这说明 V4-Flash 的架构改进、数据质量提升和训练优化，使它在更小参数预算下获得了更强表现。

第二条主线是 **Pro 的能力上限**。DeepSeek-V4-Pro-Base 在几乎所有类别上进一步提升，在知识密集评估上提升明显，同时也显著增强长上下文理解；多数 reasoning 和 code benchmark 上也超过前两个模型。论文将其定位为 DeepSeek 系列中最强的 foundation model。

从 Table 1 的部分结果看，V4-Pro 在 MMLU-Pro、MultiLoKo、Simple-QA verified、FACTS Parametric、LongBench-V2 等任务上提升尤其明显。例如 MMLU-Pro 从 V3.2 的 65.5 提升到 V4-Pro 的 73.5；Simple-QA verified 从 28.3 到 55.2；FACTS Parametric 从 27.1 到 62.6。这些指标说明 Pro 的大规模参数和数据训练显著增强了知识记忆与调用能力。

但也要注意，表格不是简单的“模型越大每项都越强”。部分代码或数学 benchmark 上，Flash 或 V3.2 可能接近甚至超过 Pro。这说明 base model 的评测结果受数据分布、评测形式、训练 recipe、模型规模和任务类型共同影响，不能只用参数量单因素解释。

## 五、关键概念速记

**Base model**：预训练后的基础模型，还没有经过完整后训练。它主要体现语言建模、知识、推理、代码、长上下文等底层能力。

**Long-tail knowledge**：低频、地区性、语言特定、专业特定或文化特定的知识。多语言语料有助于覆盖这些知识。

**Sample-level attention masking**：在 document packing 后，限制 token 只能 attend 到自己所属样本内部，避免不同样本之间互相污染。它和 causal mask 不同：causal mask 管“不能看未来”，sample-level mask 管“不能看别的样本”。

**Activated parameters**：MoE 模型中每个 token 实际调用的参数量。它通常远小于 total parameters。

**Loss spike**：训练 loss 突然异常升高，通常意味着训练动力学或数值稳定性出现问题。

**Anticipatory Routing**：用历史参数提前计算路由索引，在 loss spike 风险出现时打断 routing 与 outlier 的恶性循环。

**SwiGLU Clamping**：限制 SwiGLU 激活的数值范围，抑制异常值传播。

**Sequence length curriculum**：从短上下文逐步扩展到长上下文。DeepSeek-V4 从 4K 逐步扩展到 16K、64K、1M。

**Dense-to-sparse transition**：先用 dense attention 稳定训练，再逐步引入 sparse attention，避免一开始训练难度过高。

## 六、本节核心结论

第 4 节可以用一句话概括：

**DeepSeek-V4 的预训练不是单纯扩大模型或堆更多 token，而是通过高质量数据构造、长上下文课程训练、MoE 稳定性技巧和统一 base model 评估，系统性地打造 Flash 的参数效率和 Pro 的能力上限。**

更具体地说，4.1 证明数据侧围绕质量、多语言、长文档和上下文构造进行升级；4.2 证明训练侧围绕 Flash/Pro 两条路线、Muon 优化器、长上下文课程和训练稳定性进行设计；4.3 则验证了这些设计的结果：V4-Flash-Base 在更小参数预算下超过 V3.2-Base 的多数表现，V4-Pro-Base 则成为 DeepSeek 系列中能力最强的 base model。
