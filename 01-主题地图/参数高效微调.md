# 参数高效微调

> [!note]
> 本页只回答“如何少更新参数也能适配任务”。SFT / DPO / RLHF 是训练目标或阶段，不属于本页主线。

## 1. 概念地图

| 方法族 | 解决的问题 | 当前入口 |
|---|---|---|
| 低秩增量 | 用低秩矩阵近似权重更新，减少可训练参数 | [LoRA](../02-%E6%A6%82%E5%BF%B5%E7%AC%94%E8%AE%B0/LoRA.md) |
| 低比特适配 | 冻结或量化底座，降低训练显存 | 待补：QLoRA |
| 附加模块 | 插入小模块承接任务差异 | 待补：Adapter |
| 前缀/提示调优 | 用可训练 prefix / prompt 影响生成行为 | 待补：Prefix Tuning、Prompt Tuning |
| 全参微调对照 | 作为成本、效果和自由度参照 | 待补 |

## 2. 选择框架

| 判断维度 | 优先考虑 |
|---|---|
| 显存很紧 | QLoRA、LoRA、小 batch + gradient accumulation |
| 任务主要是格式或风格适配 | LoRA、Prompt Tuning、Prefix Tuning |
| 需要较强任务迁移 | LoRA 或全参微调对照 |
| 推理不能接受额外延迟 | 可 merge 的 LoRA |

## 3. 边界

- LoRA-SFT 的阶段归 [后训练与对齐](%E5%90%8E%E8%AE%AD%E7%BB%83%E4%B8%8E%E5%AF%B9%E9%BD%90.md)，参数更新方式从本页进入。
- 训练显存、吞吐、FSDP、checkpoint 归 [训练系统工程](%E8%AE%AD%E7%BB%83%E7%B3%BB%E7%BB%9F%E5%B7%A5%E7%A8%8B.md)。
- 部署量化默认归 [推理优化](%E6%8E%A8%E7%90%86%E4%BC%98%E5%8C%96.md)；训练时低比特底座可在本页交叉引用。
