# Obsidian 工作流

核心理念：笔记不是写完扔进去，而是让它进入系统，多条路径都能找到它——**更重要的是，每篇笔记在网络中的位置必须清晰**。

### 0. 图谱成员资格原则

**关系图谱只承载两类节点：主题页和概念笔记。** 其他所有类型的笔记（项目笔记、日志、技术报告分析、论文解读等）都不参与图谱——它们的价值在于作为素材库，后续拆分出独立概念后再进入图谱。

| 笔记类型 | 图谱 | 说明 |
|----------|:---:|------|
| 主题页 / 概念笔记 | **是** | 图谱仅由这两类节点构成 |
| 项目笔记 / 日志 / 系统页 | 否 | 各自有组织方式，不混入知识图谱 |
| 分析 / 解读笔记（报告、论文、书籍） | **否** | 参考材料，内容拆分后由各概念笔记承接 |

> [!warning] 典型误区
> 把 Qwen2.5 技术报告分析直接挂入「后训练与对齐」主题页。结果：臃肿的综合体占据图谱位置，真正有价值的知识点反而没有独立节点。
>
> 正确做法：分析笔记留在 `02` 或 `05` 作为参考材料，不挂主题页；从中拆分出的 `[GRPO](../../02-%E6%A6%82%E5%BF%B5%E7%AC%94%E8%AE%B0/GRPO.md)`、`[DPO](../../02-%E6%A6%82%E5%BF%B5%E7%AC%94%E8%AE%B0/DPO.md)` 等才是进入图谱的概念笔记。

## 一、文件夹角色

| 文件夹 | 角色 | 用途 |
|---|---|---|
| `05-资料摘录` | 收件箱 | 原始输入：对话摘录、文章片段、零散思考 |
| `04-实验与日志` | 时间线 | 过程记录：调 bug、跑模型、实验进展 |
| `02-概念笔记` | 知识库 | 概念笔记（参与图谱）+ 分析/解读笔记（不参与，作拆分素材） |
| `03-项目笔记` | 工作台 | 项目组织：微调项目、检测系统等 |
| `01-主题地图` | 分层导航 | 总图只连主题页，概念由各主题页承接 |
| `00-首页与索引` | 控制台 | 日常入口，汇总重点和常用链接 |
| `06-模板` | 后台规则 | 笔记模板，平时无需打开 |

### 1.1 链接纪律

模板页、规范页、工作流页**只链接到 `[主页](../%E4%B8%BB%E9%A1%B5.md)`，或用普通文本指向“笔记系统”**，不直接与知识概念页大量互链。这样可以避免规范示例污染未创建链接列表。

### 1.2 图谱分层原则

```
第 0 层：主页（最外层入口）
  └─ 第 1 层：总学习地图（纯导航，只连主题页）
       ├─ 第 2 层：主题页（领域聚合，承接和组织概念）
       │    └─ 第 3 层：概念页（单个技术概念的详解）
       └─ 系统层（笔记系统 → 工作流 / 模板 / 规范，独立于主知识网络）
```

#### 1.2.1 各层职责

| 层级 | 可以连接什么 | 不应该连接什么 |
|------|-------------|---------------|
| **主页** | 总地图、笔记系统、重要项目页 | 具体概念 |
| **总地图** | 主题页、少量未归属的基础组件 | 大量具体概念 |
| **主题页** | 该领域全部概念、兄弟主题页、上位/下位项目 | 跨领域的大量无关概念 |
| **概念页** | 上位主题、同级概念、下游项目 | 总图（除非尚未归属任何主题） |

> [!warning] 最常见的错误
> 创建了主题页但**没有从总图删除概念的直连线**。结果主题页只是"旁路"，总图和主题页同时连接同一批概念 → 职责重叠。

#### 1.2.2 主题页独立性检验

> **删掉总学习地图后，这个主题页及其下属概念能不能靠自己站住？**

如果不能——需要补充：方法对比表、关系说明、决策路径、与相邻主题的边界界定。

#### 1.2.3 链接降噪原则

1. **概念已归属主题页 → 不再直连总图**
2. **总图只做放权，不做聚权**——链接数应随主题页增多而减少
3. **跨主题必要连接保留，控制数量**（1-2 条即可）

## 二、新内容处理流程

```
新内容 → 按成熟度分流 → 判断类型与角色 → 整理为正式笔记 → （若为概念笔记）补链 & 挂入主题网络 & 降噪
```

### 2.1 第 1 步：按成熟度分流

- **原始材料**（对话摘录、文章片段、零散思考）→ `05-资料摘录`
- **过程记录**（实验、调试、日志）→ `04-实验与日志`
- **成熟知识**（已有体系的技术总结）→ `02-概念笔记`
- **项目相关**（完整项目的内容）→ `03-项目笔记`

### 2.2 第 2 步：判断类型与角色

先回答一个问题：**这篇笔记是一个独立的概念，还是综合性的分析材料？**

| 判断               | 类型   | 后续流程                                    |
| ---------------- | ---- | --------------------------------------- |
| 讲清楚**一个**技术点     | 概念笔记 | 完整图谱流程（必备结构 → 图谱定位 → 补三向链 → 挂入主题页 → 降噪） |
| 分析**一篇**报告/论文/书籍 | 分析笔记 | 整理好结构即可，标注可拆分出的潜在概念，**不挂主题页**           |
| 围绕**一个项目**组织     | 项目笔记 | 满足项目笔记结构，项目内部关联                         |

> 图谱是否清晰，取决于不同类型的节点有没有分层。把地图页、概念页、分析笔记混在同一层，图谱就会乱。

### 2.3 第 3 步：整理为正式笔记

判断该内容是否值得长期保留：
- **一次性内容** → 留在 `05` 即可
- **反复参考的知识** → 整理成正式笔记，迁移到对应文件夹

#### 2.3.1 必备结构

| 笔记类型 | 必备结构 |
|----------|----------|
| **概念笔记** | 摘要（`> [!note]`）+ 核心内容 + **图谱定位** + 相关概念双链 + 易错点 callout |
| **分析笔记** | 结构清晰的完整内容 + 可拆分概念标注（不需要图谱定位） |
| **项目笔记** | 项目概述 + 当前阶段/重点 + 相关知识双链 + 相关记录 |
| **日志笔记** | 时间 + 背景 + 过程 + 结论（沉淀后可拆分到概念页或项目页） |

可用模板：`[概念笔记极简模板](../../06-%E6%A8%A1%E6%9D%BF/%E6%A6%82%E5%BF%B5%E7%AC%94%E8%AE%B0%E6%9E%81%E7%AE%80%E6%A8%A1%E6%9D%BF.md)` / `[项目笔记极简模板](../../06-%E6%A8%A1%E6%9D%BF/%E9%A1%B9%E7%9B%AE%E7%AC%94%E8%AE%B0%E6%9E%81%E7%AE%80%E6%A8%A1%E6%9D%BF.md)`

满足上述要求后可自由扩展小节——按内容需要增删、改名、调整顺序。

> [!tip] 模板服务内容，不是内容服务模板
> 如果删掉几个小标题后文章更顺，就删；如果为了对齐模板硬拆出栏目但读起来突兀，就不要保留。

#### 2.3.2 图谱定位（仅概念笔记）

每篇概念笔记必须在开头或结尾包含：

```markdown
## 关联
- 属于：具体上位主题
- 相关：具体同级概念1 具体同级概念2
- 用于：具体下游项目或场景
```

### 2.4 第 4 步：补齐结构化链接（仅概念笔记）

每篇概念笔记至少补齐三类连接：

| 连接类型 | 要求 | 说明 |
|----------|------|------|
| **上位连接** | ≥ 1 | 属于哪个主题或领域 |
| **横向连接** | ≥ 2 | 和哪些兄弟概念相关 |
| **应用连接** | ≥ 1（如适用） | 在哪个项目或场景中被用到 |

以 KV Cache 为例：上位 `[推理优化](../../01-%E4%B8%BB%E9%A2%98%E5%9C%B0%E5%9B%BE/%E6%8E%A8%E7%90%86%E4%BC%98%E5%8C%96.md)` + 横向 `[Attention](../../02-%E6%A6%82%E5%BF%B5%E7%AC%94%E8%AE%B0/Attention.md)` `[Transformer](../../02-%E6%A6%82%E5%BF%B5%E7%AC%94%E8%AE%B0/Transformer.md)` + 应用“大模型推理实验”。

### 2.5 第 5 步：挂入主题网络 + 链接降噪（仅概念笔记）

#### 2.5.1 挂入对应的主题页

```
主页
└── LLM学习地图（纯导航，只连总览页和主主题域）
    ├── → LLM全流程总览
    ├── → 基础架构        → Transformer / Attention / BPE / 位置编码 / 激活函数 / VLM / Chat Template
    ├── → 预训练          → Scaling Law / 数据工程 / 训练目标
    ├── → 参数高效微调    → LoRA / QLoRA / Adapter
    ├── → 后训练与对齐    → SFT / RLHF / PPO / DPO / GRPO / Reasoning RL
    ├── → 推理优化        → KV Cache / Flash Attention / MQA-GQA / MLA / vLLM
    └── → 训练系统工程    → 显存 / 并行 / 吞吐 / checkpoint / veRL / Ray / FSDP
```

> 当某主题下笔记超过 5-8 篇时，从总图拆分为独立主题页，并**同步从总图删除这些概念的直连**。
> [训练系统工程](../../01-%E4%B8%BB%E9%A2%98%E5%9C%B0%E5%9B%BE/%E8%AE%AD%E7%BB%83%E7%B3%BB%E7%BB%9F%E5%B7%A5%E7%A8%8B.md) 是横切透视层：当概念能明确归属某个生命周期阶段时，优先挂入对应主主题页；只有显存、吞吐、并行、调度、稳定性等跨阶段问题，才从训练系统工程进入。

#### 2.5.2 链接降噪（与挂入同步执行）

| 检查项 | 动作 |
|--------|------|
| 概念已归属主题页 | 从**总图**中删除该概念的直连 |
| 两个主题页同时连接同一概念 | 保留主题页连接，删除总图直连 |
| 总图链接数量膨胀 | 定期审查：总图应只含「主题页入口 + 未归属基础组件」 |

> 降噪的本质不是删除关系，而是让最主要路径更清晰。删掉直连不会让检索变差——通过 `主页 → 总图 → 主题页 → 概念` 仍能到达，且路径更短。

#### 2.5.3 固定整理指令

整理笔记时，将以下任务交给 Claude Code：

```
请读取我的工作流文件（00-首页与索引/工作流.md）第二章「新内容处理流程」，
然后把当前内容整理成一篇 Obsidian 笔记，要求：

1. 判断类型：concept（独立概念）/ analysis（报告分析）/ project / log
   - concept → 参与图谱，走完整图谱流程
   - analysis → 不参与图谱，整理结构 + 标注可拆分概念
   - project / log → 满足各自必备结构即可

2. 若为概念笔记：
   a. 满足概念笔记必备结构（参考 06-模板/概念笔记极简模板）
   b. 包含「图谱定位」区块（## 关联：属于/相关/用于），上位指向具体主题页
   c. 至少 2 个同级相关概念双链
   d. 检查总图（LLM学习地图）：确认无该概念直连
   e. 保存路径：02-概念笔记/

3. 若为分析笔记：
   a. 整理好结构和内容，不需要图谱定位
   b. 不挂入任何主题页
   c. 标注可拆分出的潜在概念知识点
   d. 保存路径：02-概念笔记/

4. 通用要求（所有类型）：保持知识点完整、合并碎片化小节、callout 替代滥用加粗、对比信息用表格
5. 若属于模板/规范/工作流类，只挂到「笔记系统」页
```

## 三、笔记生成规范

适用于所有正式笔记的格式细节。第二章已覆盖必备结构和图谱定位，本章节补充格式规则。

### 3.1 样式

字体 LXGW WenKai（正文）+ LXGW WenKai Mono（代码）；浅黄背景（`claude-like.css`）；行高 1.85，字号 17px，限宽 780px 居中；代码块深底浅字。

### 3.2 去AI味

- **滥用加粗** → 改为自然行文衔接，全文不超过 3-5 处核心关键点
- **模板化引导语**（"从XX角度看"）→ 直接说事，去掉套话
- **机械总结段** → 保留但去掉多余加粗

### 3.3 排版

- 合并碎片化小节，用自然段落过渡替代大量短标题
- 关键概念用 callout（`> [!tip]` / `> [!note]` / `> [!warning]`）呈现
- 对比类信息用表格，列表只用于真正的枚举场景
- **保留必要的小标题序号**：多层级笔记中，标题应带编号（如 `1.1`、`1.2.1`），方便定位和引用；不需要编号的短标题可以不加，但不要为了"去AI味"把所有序号都删掉

### 3.4 内容完整性

尽量保持原有知识点完整，可重新组织和表达方式，但不随意删减。表述不清或有误的地方修正表达而非直接删除。

### 3.5 公式

行内 `$...$`，独立 `$$...$$`；检查变量名冲突；公式前后不加多余引导句。

## 四、查看笔记的四种方式

| 方式 | 适合场景 | 入口 |
|------|---------|------|
| **文件夹浏览** | 已知类别，直接定位 | `02`、`04` 等 |
| **主页 & 主题地图** | 回顾学习、按主题浏览 | `00`、`01` |
| **双链 & 反向链接** | 围绕一个点往外扩展 | 笔记正文 + Backlinks |
| **全局搜索** | 只记得关键词 | Obsidian 搜索框 |

## 五、日常使用规则

- **写入时**：新内容先进 `05` 或 `04`，不纠结完美分类
- **沉淀时**：先判断类型和角色，再整理进 `02` 或 `03`
- **联网时**（仅概念笔记）：补齐三向链接，挂入主题页，同步降噪
- **定期审查**：每新增 5 篇笔记后，检查总图放权和主题页独立性
- **查看时**：从 `00` 和 `01` 的各主题页开始

## 六、图谱自检清单

### 6.1 单篇检查

**概念笔记：**
- [ ] 有上位主题？（具体主题页，非总地图）
- [ ] 有同级邻居？（≥ 2 个横向链接）
- [ ] 有应用去向？
- [ ] 已挂入对应的主题页？

**非图谱笔记（分析/项目/日志）：**
- [ ] 未挂入任何主题页？
- [ ] 分析笔记是否标注了可拆分概念？

### 6.2 全局检查（每新增 5 篇笔记后执行）

- [ ] 总图直连数是否随主题页增多而减少？
- [ ] 删掉总图后各主题簇能否靠自己站住？
- [ ] 有没有总图和主题页同时连接同一概念的情况？
- [ ] 系统页是否只挂在“笔记系统”或 [主页](../%E4%B8%BB%E9%A1%B5.md) 下？

## 七、示例

### 7.1 正例：概念笔记 —— KV Cache

1. 存入原始材料：`05-资料摘录/KV Cache 学习摘录 2026-04-08.md`
2. 判断：讲清楚一个独立技术点 → **概念笔记**
3. 整理：`02-概念笔记/KV Cache.md`，含摘要、核心内容、**图谱定位**（属于：推理优化 / 相关：Attention、Transformer / 用于：大模型推理实验）
4. 补链：上位 `[推理优化](../../01-%E4%B8%BB%E9%A2%98%E5%9C%B0%E5%9B%BE/%E6%8E%A8%E7%90%86%E4%BC%98%E5%8C%96.md)` + 横向 `[Attention](../../02-%E6%A6%82%E5%BF%B5%E7%AC%94%E8%AE%B0/Attention.md)` `[Transformer](../../02-%E6%A6%82%E5%BF%B5%E7%AC%94%E8%AE%B0/Transformer.md)` + 应用“大模型推理实验”
5. 挂入 + 降噪：加入 `01-主题地图/推理优化.md`，确认总图无 `[KV Cache](../../02-%E6%A6%82%E5%BF%B5%E7%AC%94%E8%AE%B0/KV%20Cache.md)` 直连

### 7.2 正例：分析笔记 —— Qwen2.5 技术报告

1. 存入原始材料：`05-资料摘录/qwen2.5/整体架构.md`
2. 判断：综合分析一篇报告 → **分析笔记**
3. 整理：`02-概念笔记/Qwen2.5 训练链路架构.md`，整理结构、去AI味、表格化
4. **不挂任何主题页**，标注可拆分概念：长上下文扩展策略、data mixture 方法等
5. 后续从中提取独立概念（如“Qwen2.5 长上下文训练”），这些才进入图谱

### 7.3 反例

- **概念笔记未降噪**：写了 DPO 笔记并挂入「后训练与对齐」，但没有从总图删除 DPO 直连 → 总图和主题页职责重叠
- **分析笔记强行挂图谱**：把 Qwen2.5 分析挂入主题页 → 臃肿综合体占据图谱位置，真正有价值的知识点没有独立节点
