# LLM-WIKI 工作流

## 1. 仓库分层

| 层级 | 目录 | 作用 |
|---|---|---|
| 控制层 | `00-首页与索引`、`AGENTS.md` | 主页、索引、规则、处理日志、自检清单 |
| 主题导航层 | `01-主题地图` | 组织主题路径和概念入口 |
| 正式知识层 | `02-概念笔记` | 沉淀可复用概念、机制、对比和方法 |
| 项目应用层 | `03-项目笔记` | 保存项目结构、项目总结、代码解析和应用案例材料 |
| 过程记录层 | `04-实验与日志` | 保存实验过程、排障记录、阶段日志和产物 |
| 资料来源层 | `05-资料摘录` | 登记官方来源链接、报告/论文笔记、阅读摘录和资料卡片 |
| 模板层 | `06-模板` | 保存概念、项目、资料卡片等模板 |
| 临时 Inbox | `07-待整理` | 临时材料，只进不久留 |
| 附件层 | `08-图片` | Canvas、图片和其他附件 |

## 2. Ingest：资料进入流程

处理新资料时，按以下顺序执行：

1. 读取资料或资料摘录，确认来源位置。
2. 判断资料类型：`paper` / `report` / `code` / `experiment-log` / `chat-note` / `raw-note`。
3. 判断处理目标：只归档 / 摘要 / 拆概念 / 更新概念页 / 更新项目页。
4. 生成或更新资料卡片，并在 [资料索引](../../05-%E8%B5%84%E6%96%99%E6%91%98%E5%BD%95/%E8%B5%84%E6%96%99%E7%B4%A2%E5%BC%95.md) 记录处理状态。
5. 提取核心概念和潜在概念页。
6. 检查是否已有相关概念页，优先更新已有页面。
7. 必要时创建新的概念页，并补齐上位主题、相关概念、来源资料。
8. 更新相关主题地图，让主题页承接新概念。
9. 如果资料与项目相关，更新项目页或实验日志索引。
10. 更新 [index](index.md) 和 [LLM-WIKI处理日志](LLM-WIKI%E5%A4%84%E7%90%86%E6%97%A5%E5%BF%97.md)。

## 3. Compile：资料编译规则

资料不是 Wiki 本体。PDF、章节精读、报告摘录、对话摘录应保留在 Source 层，经过整理后再编译成：

- 概念页
- 主题页
- 项目判断
- 实验结论
- 方法对比页
- 总览页

编译时遵守：

- 不把 PDF 直接挂入主题地图。
- 不把项目日志直接混入概念图谱。
- 不把多个不同主题强行合并成一篇大笔记。
- 对不确定结论标注“待验证”。
- 每个长期可复用概念应能追溯到来源资料。

## 4. Query：查询流程

回答问题时优先读取：

1. [主页](../%E4%B8%BB%E9%A1%B5.md)
2. [index](index.md)
3. 相关主题地图
4. 相关概念页
5. 相关项目页或实验日志
6. 必要时回查 `05-资料摘录`

如果回答产生了长期有价值的结论，应建议写回 Wiki，并说明建议写入哪个页面。

## 5. Lint：自检流程

每完成一个主题、批量整理一次资料，或新增 5 篇正式笔记后，执行自检：

- 是否有孤立概念页？
- 是否有重复概念或同义页面？
- 是否有概念页没有上位主题？
- 是否有概念页没有横向链接？
- 是否有主题页没有更新？
- 是否有总图和主题页重复直连同一概念？
- 是否有资料已摘要但未进入概念页？
- 是否有项目经验值得抽象成概念？
- 是否有长期停留在 `07-待整理` 的材料？
- 是否有过期结论或待验证结论需要标记？
- 主题地图重写后，是否同步更新了 [主页](../%E4%B8%BB%E9%A1%B5.md)、[index](index.md) 和 [LLM-WIKI处理日志](LLM-WIKI%E5%A4%84%E7%90%86%E6%97%A5%E5%BF%97.md)？

自检时先输出报告，除非用户明确要求，不要自动批量修复。

## 6. 资料状态

[资料索引](../../05-%E8%B5%84%E6%96%99%E6%91%98%E5%BD%95/%E8%B5%84%E6%96%99%E7%B4%A2%E5%BC%95.md) 中的状态只使用以下值：

| 状态 | 含义 |
|---|---|
| `raw` | 只是保存，还没处理 |
| `summarized` | 已有摘要或章节笔记 |
| `extracted` | 已抽出概念候选 |
| `integrated` | 已更新到概念页和主题地图 |
| `archived` | 暂时只归档，不处理 |
